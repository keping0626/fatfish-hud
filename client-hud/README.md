# 大肥鱼的hud · 局内拾取提示（客户端插件）

> 作者：**deepseek + keping**。插件目录名、dll 文件名、F12 显示名三者统一为 **大肥鱼的hud**（搜「大肥鱼」即可找到）；
> GUID `deepseek.keping.raidpickuphint` 决定配置文件 `BepInEx\config\deepseek.keping.raidpickuphint.cfg`。
> 程序集**内部名**仍是 `RaidPickupHint`（ASCII —— BepInEx 只按文件加载，文件名与程序集名可以不同）。

raid 中捡起物品时，HUD 立刻用**蓝色**提示这个物品被**哪个藏身处设施 / 哪个任务**需要、还差多少个。

```
【大肥鱼提醒您：固体燃料 ×2
藏身处·休息室 级1→2｜需3｜仓0+局2｜还差1｜战局内】
```

**括号规则（只有两种形态）**：要么整条被 `【】` 包裹（含前缀，默认），要么整条**完全不带**括号。
不存在"只有前缀带括号"的中间形态；若把 `【】` 也写进了"消息前缀"配置，插件会自动剥掉，不会出现 `【【…】】`。
`仓X+局Y` = 仓库里有 X 个 + 本局已捡 Y 个（两者合计参与"还差多少"的计算）。

屏幕上有**两块常驻清单**（各自独立开关；**默认目标清单在左、本局清单在右**，位置都能在 F12 里改）：

| 清单 | 内容 | 生命周期 |
|---|---|---|
| **本局拾取**（`开关 → 常驻清单`） | 本局捡到的、有需求的物品 | 每局独立，出局即清空 |
| **目标清单**（`目标清单 → 启用目标清单`） | 你自己设定要盯的任务 / 藏身处设施 / 物品 | **跨局保留**，凑齐或局数用尽才移出 |

```
目标清单（2 项）
▸ 荣耀展柜 级0→1（剩3局）
  钉子 还差3
  （已够 1/2）
▸ 信号 - 2 进行中（剩2局）
  CPU（电脑CPU） 还差3
  …另有 2 项
```

按 **F9**（可改）打开管理面板，从「任务 / 藏身处设施 / 物品」三组里点「加入」即可；
也可以直接手工编辑 `BepInEx\config\deepseek.keping.raidpickuphint.targets.json`（游戏内 30 秒热加载）。

**自定义图片（v0.1.7）**：每条浮动提示最前面可以放一张自己的小图（例如 Q 版小人），
提示条与两块清单也能换成自己的背景板——把图丢进 `BepInEx\config\deepseek.keping.raidpickuphint.images\`，
在 F12「图片」分节里填文件名，游戏内 **2 秒**自动生效，不用重启。

## 数据流

```
存档 + 任务库 + 藏身处库
        │
        ▼  D:\tkf\xuqiu\quest_hideout_checker.py   （已有的核对工具，默认就导出）
   需求快照 needs_snapshot.json                     物品 → 各需求来源 + 需要数 + 仓库持有
        │
        ▼  本插件读取（30 秒内热更新）
   局内拾取事件 ──► 命中需求则弹提示 + 更新角落常驻清单
```

**为什么要快照而不是实时问服务端**：SPT 局内拾取不经过服务端（详见 PickupTrackerServer 的结论），
而"谁需要这个物品、仓库里有多少"是**局外状态**，进局后不会变——所以一份进局前生成的快照足够，
且不依赖任何第三方 mod 的内部契约。

跑一次 `D:\tkf\xuqiu\启动_需求核对.bat` 就会顺带刷新快照；游戏内 30 秒内自动生效（无需重启游戏）。

## 挂钩点与过滤规则

挂钩 `EFT.InventoryLogic.ItemController.RaiseAddEvent(AddItemEventArgs)`（Harmony Postfix）。
该方法声明为 `virtual final`（子类不 override），patch 基类即覆盖全部调用路径；
全程序集反查其调用者仅 7 处，局内拾取必走
`ItemAddress.RaiseAddEvent → IItemOwner.RaiseAddEvent → ItemController.RaiseAddEvent`。

三层过滤（缺一会产生噪音）：

1. **落点所有者必须是本机玩家的 InventoryController** —— 排除交易、跳蚤挂单、AI、其他玩家
2. **排除武器/弹药内部槽** —— 上膛（`patron_in_weapon`）、装弹（`patron_in_mag` / `cartridges`）、
   改枪（`mod_*`）都是客户端新生成 itemId，不是拾取。
   （服务端侧曾因 SA58 上膛多记 1 发 M993，这里是它的客户端等价噪音）
3. **排除进局时就已经在自己身上的物品 id** —— 背包内整理/挪动不该算拾取

只在**真正的战局**内提示（出局或进藏身处都会自动清空本局计数与清单）。

> **藏身处不算战局**（v0.1.4 起，实机踩坑后修）：藏身处里 EFT **同样会创建** `GameWorld` 与主玩家
> （类型是 `EFT.HideoutPlayer`，继承 `EFT.LocalPlayer`），而那一刻 `player.Inventory` 是**整份 profile**
> （含仓库，实机实测 1821 件）。若不排除，在藏身处交易 / 收邮件 / 整理仓库都会被当成"局内拾取"而弹提示。
> 判据＝主玩家类型 `is HideoutPlayer`，再用 `GameWorld.LocationId` 含 `hideout` 兜底。

## 目录结构

```
BepInEx\plugins\大肥鱼的hud\
├── 大肥鱼的hud.dll           ← 插件本体（BepInEx 加载；程序集内部名仍为 RaidPickupHint）
├── needs_snapshot.json       ← 需求快照（由 quest_hideout_checker.py 生成）
├── Plugin.cs                 ← 插件入口 / 配置 / 快照与目标清单加载
├── PickupWatcher.cs          ← 拾取 hook 与三层过滤 + 进局/出局判定
├── TargetList.cs             ← 目标清单（跨局）：增删 / 展开 / 局数结算（纯逻辑，可离线自检）
├── TargetPickerUi.cs         ← F9 目标管理面板（IMGUI）
├── HintText.cs               ← 文案生成（纯逻辑，可离线自检）
├── HintHud.cs                ← IMGUI 渲染（通知条 + 本局清单 + 目标清单）
├── UiFont.cs                 ← 系统中文字体（IMGUI 默认字体无中文）
├── RaidHintState.cs          ← 本局状态（已捡计数 / 清单行）
├── NeedsSnapshot.cs          ← 快照数据模型与解析
├── ImagePath.cs              ← 图片路径解析（纯逻辑，可离线自检）
├── ImageStore.cs             ← 图片加载 / 缓存 / 2 秒热重载（Unity 侧）
└── Directory.Build.props     ← 把 obj 移出插件目录
```

数据文件（在 `BepInEx\config\` 下，与 `deepseek.keping.raidpickuphint.cfg` 同目录）：

```
deepseek.keping.raidpickuphint.cfg           ← F12 配置
deepseek.keping.raidpickuphint.targets.json  ← 目标清单（跨局持久；可手工编辑，30 秒热加载）
deepseek.keping.raidpickuphint.images\       ← 你的自定义图片（PNG/JPG）+ 插件写的 说明.txt
```

```json
{
  "schema": 1,
  "targets": [
    { "kind": "item",    "tpl": "590c31c586f774245e3141b2", "name": "钉子",     "roundsLeft": 3 },
    { "kind": "hideout", "label": "荣耀展柜", "stage": "级0→1", "name": "荣耀展柜", "roundsLeft": 3 },
    { "kind": "quest",   "label": "信号 - 2", "stage": "进行中", "name": "信号 - 2", "roundsLeft": 0 }
  ]
}
```

`kind` 三种：`item`（用 `tpl`）、`quest` / `hideout`（用 `label` + `stage`，与快照里的来源标签一致）。
`roundsLeft` = 剩余局数，**0 表示永久**。`stage` 留空表示该来源的全部阶段。

## 目标清单（跨局购物清单）

**为什么要有它**：拾取提示是被动的（捡到了才告诉你）；目标清单是主动的待办——
你先把"这局要凑什么"列出来，进局后它一直挂在屏幕上，捡到相关物品时还会弹"目标完成 ✔"。

**三个来源**（都来自需求快照，所以永远和当前进度一致）：

| 来源 | 加进去之后盯什么 | 适合场景 |
|---|---|---|
| **任务** | 该任务阶段需要的**全部**物品 | 准备做某个任务，一次把材料列全 |
| **藏身处设施** | 该设施**下一级**需要的全部物品 | 准备升级某个设施（如靶场 级1→2 的十项材料） |
| **物品** | 单个物品 | 临时想盯一件东西（如钉子），不关心它属于谁 |

**两种添加方式**：

1. **游戏内 F9 面板**（默认热键，可在 F12 改）：四个标签页 `任务 / 藏身处设施 / 物品 / 当前目标`，
   带搜索框，点「加入」即写入并落盘；「当前目标」页显示每条的进度（`2/5 已够`）与剩余局数。
2. **手工编辑文件**：`BepInEx\config\deepseek.keping.raidpickuphint.targets.json`，格式见上面的目录结构一节。
   保存后游戏内 30 秒内自动热加载；插件自己写文件时也会保留你手写的条目。

**生命周期规则**：

- 每条目标加入时带一个**剩余局数**（默认取 F12 里的「目标存活局数」，默认 3；`0` = 永久）。
- **每撤离一次**（真正出局）剩余局数 −1，归零即自动移出；**进藏身处不算一局**，不会吃掉局数。
- 本局**凑齐**的目标：立刻弹一条「目标完成 ✔ …（回主菜单后自动移出目标清单）」，
  回主菜单（出局结算）时自动移出——所以目标清单会自己收敛，不需要你手动清理。
- 判定口径与提示一致：**仓库持有量 + 本局已捡 ≥ 需求** 才算够（快照里的仓库量是进局前那一刻的值）。

## 自定义图片（v0.1.7 起；v0.1.9 起三块区域各配一张底图）

给 HUD 加上自己的图：**两类提示各自的小图**（例如捡起用一张、目标完成用另一张），
以及**三块区域各自的背景图**（浮动提示条 / 本局拾取清单 / 目标清单）。

**图片放哪**：`BepInEx\config\deepseek.keping.raidpickuphint.images\`
插件首次启动会自动创建这个目录，并在里面写一份 `说明.txt`（给你看的，可以改，插件不会覆盖）。
想换个地方也行：改 F12 的「图片 → 图片目录」。

**怎么指到图**——「文件名」和「完整路径」两种写法都支持：

| F12 里填 | 效果 |
|---|---|
| `小人.png` | 去**图片目录**里找这个文件 |
| `小人` | 省略扩展名也能认（依次试 `.png` / `.jpg` / `.jpeg`） |
| `D:\我的图\小人.png` | 按**完整路径**读，不受图片目录限制 |
| （留空） | 不显示这张图 |

**格式**：PNG（推荐，支持透明）或 JPG。GIF / BMP 等 Unity 解不出来，会在日志里记一条告警。

**生效时机**：**不用重启游戏**。放好图、或覆盖同名文件后 **2 秒内**自动换新；
文件还没放好时日志会写一条 `找不到图片「…」`，之后放好同样 2 秒内生效。

**建议尺寸**（不是硬要求，都会按比例缩放）：

| 用途 | 建议 | 说明 |
|---|---|---|
| 提示条小图标（捡起等普通提示） | 正方形、**PNG 带透明**、64~256 px | 显示高度由「小图标高度」控制（默认 28），宽度按原图比例 |
| 完成提示小图标（「目标完成 ✔」） | 同上，另配一张 | 留空 = 跟随上面那张。两张分开配就是「捡起用小人 A、完成用小人 B」 |
| 三块区域的背景图 | 横长条、PNG 或 JPG 都行，**不用抠透明** | 图片越花，越要把「不透明度」调低（见下）；插件会自动给文字加黑描边 |

> **关于透明通道（重要）**：只有 **PNG** 能带透明。**JPG 没有透明**，用来当**小图标**会显示成一个**方形小色块**
> ——提示条本身是半透明黑底，所以你会看到一块方块压在文字左边。想让小人「浮」在提示条上，就换 PNG 并抠好底。
> **但背景图不需要抠透明**：底图是"垫在文字下面"的，透明度由「不透明度」选项控制，黑白底都无所谓。
>
> **大图也没问题**：超过 2048px 的图插件照常加载（并在日志里提示「偏大」），显示时自动缩放
> （内部开了 mipmap，缩小不会有锯齿）；但先用图像工具缩到 1024px 以内会更省显存。

**背景图会不会把文字压住（v0.1.10 专门处理了这件事）**：会——尤其人物插画里浅色的脸正好落在文字下时，
蓝色小字几乎读不出来（离线按真实像素模拟过）。所以插件做了两层保底，**不需要你手工处理素材**：

1. 配了底图的区域，会**先铺一层纯黑半透明底、再叠你的图** —— 文字下面永远有暗衬；
2. 区域内文字会自动**描 1px 黑边**（只在配了底图时才描，纯黑底不描、省绘制）。

仍然觉得太花就调低不透明度：`清单背景不透明度` 默认 **0.45**，调到 **0.25~0.30** 基本只剩一层色调。
开发期用 Pillow 按插件的真实绘制几何离线合成了对比图（不用进游戏就能看效果）；该模拟脚本未随本仓库发布。

**怎么验证两张图都配对了**：按 **F10** 会**弹两条** —— 第一条是普通拾取样式（用「提示条小图标」），
第二条是「目标完成 ✔（自测）」样式（用「完成提示小图标」）。不用进局、不用捡东西，一眼就能看出哪张配错了。
（只在你填了「完成提示小图标」时才会弹第二条。）

**关于素材本身（踩过的坑）**：

- **白底图一定要先抠成透明 PNG**，否则在提示条上就是一个**白方块**（提示条是半透明黑底，对比非常刺眼）。
- **图里带的台词 / 水印，缩到 24~48px 只会糊成几条横线**，还占掉三分之一高度、把人物挤小 —— 建议裁掉，只留人物。
- 抠图要做三件事：**白底泛洪抠透明**（只抠「与画面边缘连通」的白色，人物身上的白蕾丝、白围裙不会被误伤）
  → **裁紧**到非透明像素 → **裁掉底部台词**。开发期用的处理脚本未随本仓库发布，
  照这个思路用 Python + Pillow（或 Photoshop 魔棒）都能做；成品是**带透明通道的 PNG**，放进图片目录即可。

**两块清单摆哪**：目标清单默认在**屏幕左侧**（F12「目标清单 → 靠左显示」），
本局拾取清单的位置由「外观 → 靠右显示」单独控制——两块分开摆，右边就不会挤。

**诊断表**（2026-10-12 两轮实机后定型）：

| 日志现象 | 结论 | 处置 |
|---|---|---|
| 有 `Awake 已回调` + 有 `HUD 收到 OnGUI 回调`，但屏幕仍无输出 | 回调正常，问题在绘制/可见性 | 看 `HUD 渲染异常` 告警 |

| 有 Awake、无 `OnGUI 回调`，且 F10 时**没有** `HUD 实例为空` | Unity 不回调 IMGUI | 用 `显示方式 = NativeOnly`，靠游戏原生通知 |
| 连 `HUD 组件挂载成功` 都没有 | 组件挂载就失败 | 把日志发我 |
| **撤离回主菜单后常驻清单还挂在屏幕上** | 出局时只清了浮动队列、没清清单数据源 | **v0.1.5 已修**（`LeaveRaid` 里补 `ResetForRaid`） |
| **第一次按 F10 / 第一次捡到东西，提示要等几秒才出现** | 图片是在**绘制路径**里首次同步加载的（PNG 解码 + mipmap + 上传），字体字形也是首次渲染才栅格化 | **v0.1.11 已修**（进局前预热）；日志可查 `图片预热完成：N 项已进缓存` |
| **在 F12 里拖动滑块时界面卡住、日志反复刷 `图片已加载：…`** | 旧版每次设置变更都清空并重载**全部**图片（拖滑块是连续触发的） | **v0.1.12 已修**（只有图片配置真变了才重载） |

> **⚠ 已踩过的坑（v0.1.0–v0.1.2，2026-10-12 两轮实机定位）**
>
> 不要在插件 `Awake` 里用 `new GameObject(...)` + `DontDestroyOnLoad(...)` 挂 HUD。
> 插件 `Awake` 发生在游戏**首个场景加载之前**，这样建出来的独立对象会在游戏加载主场景时被连带销毁：
> 加载时日志是 `HUD 组件挂载成功；Instance=已就绪`，而进主菜单按 F10 却报
> `HUD 实例为空，自绘提示被跳过`（Unity 对已销毁对象的 `!= null` 为 false）——
> 于是自绘 IMGUI **整整一帧都没被回调过**，屏幕上永远没有自绘提示，而**原生通知照常工作**
> （所以玩家看到的那行字其实是游戏通知，不是 HUD）。
> **判别证据**：F10 时日志出现 `HUD 实例为空` + 全日志零处 `OnGUI`。
> **正确做法**：挂到插件自身的 GameObject（BepInEx 的 manager，随游戏全程存活），
> 并在 `Update` 里检测 `HintHud.Instance == null` 时自愈重建。

对照实验：按 **F12** 看能否打开 BepInEx 配置管理器（它同样是 IMGUI）。
F12 有窗口 ⇒ IMGUI 本身没坏，问题在本插件（优先查上表的"宿主对象被销毁"一行）。

- **完全没有本插件的日志** → 插件没被加载：确认 `大肥鱼的hud.dll` 在 `BepInEx\plugins\大肥鱼的hud\` 下
- **有"拾取钩子已挂载"但捡东西没提示** → 分类排查：
  - 按 **F10** 弹自测提示：能弹 → HUD 与字体正常，问题在拾取判定；不能弹 → HUD 渲染问题
  - 捡的东西**不在需求清单**里（快照只含"有需求"的 82 种物品）→ 本就不该提示
  - 快照过期：重跑 `tools\启动_需求核对.bat`，30 秒内自动生效
- **中文显示成方块** → 系统缺中文字体，改 `[外观] 字号` 或装微软雅黑
- **日志出现 `藏身处场景：不计入战局（LocationId=…，玩家类型=EFT.HideoutPlayer）`** → 正常：
  藏身处（含里面的射击场）被正确识别并排除，该场景不产生拾取提示（v0.1.4 起）

## 性能说明（针对塔科夫的单核/GC 敏感）

- 挂钩只在物品**加入容器**时触发，判定是几次字典查找与引用比较，无分配
- 配置**只在变更时**同步（`SettingChanged` 事件），不做每帧字符串解析
- 常驻清单文本**只在内容变化时**重建（`PanelVersion` + 宽度/条数缓存），不做每帧拼串
- HUD 在无提示时 `OnGUI` 直接返回
- 自定义图片**只在内存缓存里查**（`ImageStore.Get` 不做任何磁盘 I/O，每帧可安全调用）；
  换图靠 `Poll` 每 **2 秒**检查一次文件时间戳，**没配图片时立即返回**，不扫描目录
- 文字描边（v0.1.10）**只在配了底图的区域**生效：每帧多 4 次 `GUI.Label`（无字符串分配），
  没配底图时完全不描——把开销绑定在"用户确实用了底图"这一前提下
- 图片与字体在**进局前预热**（v0.1.11）：`ImageStore.WarmUp()` 每帧最多加载 1 张（不把多张解码挤进同一帧），
  跑完即置位不再检查；字体预热只在第 1 帧 `OnGUI` 做一次。两者都发生在"玩家还没进局"的时候，
  所以界面上看不到卡顿——换来的是**第一次弹提示不再等几秒**

## 已知限制

- **ALT+F4 强退**那一局：提示本身照常显示（提示是实时的，不依赖结算），但服务端侧的
  `pickups.json` 记录不到（客户端不回传 profile）
- **同款堆叠合并**（捡到的子弹并进已有堆叠）：物品 id 可能是新生成的，能被捕获；
  但若客户端复用原堆叠对象，则可能漏提示
- 提示依赖快照的新鲜度：接了新任务 / 升了藏身处后需重跑一次核对工具（或直接跑 bat）
- **藏身处不提示**（v0.1.4 起有意为之）：在藏身处（含内部的射击场）整理仓库、交易、收邮件都不算"局内拾取"

  提示数据永远不刷新）、4 个 `_tools` 脚本的快照路径、7 个图片处理脚本的图片目录。

  在写完字段后**无条件**调用 `ImageStore.Invalidate()`，而 F12 里拖滑块（字号、不透明度、时长……）
  是**每次值变化都触发** `SettingChanged` 的，于是会变成「边拖边销毁 + 重新解码 4 张 1MB 级 PNG」，
  设置界面直接卡住。现在加了图片配置签名（`ImageSignature`＝开关 / 目录 / 两个图标 / 三张底图），
  **只有签名变了才清缓存**；字号、不透明度、填充方式这类纯绘制参数改了**不再重载图片**。
- **v0.1.11**（2026-10-12）：**预热图片与字体**——修「第一次弹提示要等几秒」。
  实测日志实证：`自测提示已弹出` 之后才出现 `图片已加载：捡起_图标_无台词.png`／`完成_图标.png`，
  说明 `ImageStore.Get` 是在**绘制路径**里首次同步加载的（PNG 解码 + mipmap 生成 + 上传显存），
  两张 1MB 级 PNG 挤在同一帧。更隐蔽的是「本局清单背景」——那块清单只在有内容时才画，
  所以**进局后第一次捡到东西**才会首次解码那张 1.3MB 的图，玩家会以为没提示。
  现在：`ImageStore.WarmUp()` 由 `Plugin.Update` 调用，**每帧最多加载 1 张**，
  在进局前（游戏还在加载的那几帧）把 5 个图片位置全部预热进缓存；
  字体则在第 1 帧 `OnGUI` 预热一次（建字体对象 + `CalcSize` 样本触发中文字形栅格化）。
  日志新增 `图片预热完成：N 项已进缓存` 便于核对。
- **v0.1.10**（2026-10-12）：**背景图不再压住文字**——配了底图的区域改为「先铺纯黑半透明底 → 再叠用户的图」，
